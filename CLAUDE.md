# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Psi Mobile is an iOS XMPP client (SwiftUI, iOS 17+, iPhone only, portrait) that copies the look of Psi+ and implements PGP per XEP-0027, staying interoperable with Psi+/Gajim. Code comments, UI strings, scripts and `AppStore/` texts are in Russian; keep them that way.

## Commands

```bash
./scripts/run.sh                 # build and launch in an iPhone simulator
./scripts/run.sh device [TEAM]   # build, install and launch on a cabled iPhone; TEAM is detected from the keychain if omitted
./scripts/build-psipgp.sh        # rebuild Frameworks/Psipgp.xcframework (run.sh does this only if it is missing)
./scripts/release-build.sh       # size-optimized Release without local paths; `archive TEAM` signs, `upload TEAM` sends to App Store Connect
swift test --package-path Packages/libidn-framework   # the only automated Swift tests
xcodegen generate                # regenerate PsiMobile.xcodeproj from project.yml
./scripts/import-psi.py [JID]    # copy the account and PGP keys from Psi+ on this Mac to the cabled iPhone (Debug builds)
```

`run.sh` filters xcodebuild output down to errors and the result line; the full log is in `build/run.log`. Derived data is in `build/dd`.

Build without launching (take the UDID from `xcrun simctl list devices available`):

```bash
xcodebuild -project PsiMobile.xcodeproj -scheme PsiMobile -configuration Debug \
  -destination "id=<SIM_UDID>" -derivedDataPath build/dd CODE_SIGNING_ALLOWED=NO build
```

There is no linter, and the app itself has no tests. `build-psipgp.sh` runs the Go interop tests (`Go/psipgp/psipgp_test.go`) against real `gpg` and refuses to build the framework if they fail, so run it after any change in `Go/psipgp`. The Go package has no `go.mod` of its own: the script copies it into the pinned GopenPGP checkout and builds it there.

Demo data without a server (Debug, simulator): `xcrun simctl launch <SIM_UDID> am.local.psimobile -psiDemo YES` plus `-psiDemoChat YES` (open a chat), `-psiDemoMessages N`, `-psiDemoRoom YES` (a room), `-psiDemoRoomEdge YES` (room edge cases and forged stanzas), `-psiDemoWipe YES` (runs `wipeAccount()` at launch). `PsiDemo` is compiled only in Debug.

## Project setup

- **Not in git:** `PsiMobile.xcodeproj` (generated by XcodeGen; `run.sh` and `release-build.sh` always regenerate it) and `Frameworks/Psipgp.xcframework` (built by `build-psipgp.sh`). Only `PsiMobile.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` is tracked, because it pins the transitive SPM dependencies. Change `project.yml`, not the project, and regenerate after adding or removing source files.
- `Frameworks/Psipgp.xcframework` is built locally with gomobile from `Go/psipgp`, a thin wrapper over GopenPGP. It is linked with `embed: false`. Its Swift API is gomobile-generated; only `PGPService` talks to it.
- XMPPFramework comes through SPM, pinned to a commit in `project.yml`. GopenPGP and gomobile versions are pinned in `scripts/build-psipgp.sh`.
- `Packages/libidn-framework` overrides XMPPFramework's dependency of the same name. It reimplements stringprep on Foundation with no GNU libidn (LGPL) code. Its output affects JID comparison and SCRAM login hashes, so keep behavior stable.
- Keep the app small: most of the binary is Go code, so add to `Go/psipgp` only what the app calls. Size flags live in `scripts/release-build.sh` because command-line settings also reach SwiftPM packages; symbol stripping is in `project.yml` because it must apply only to the app target.
- `Resources/Licenses.txt` is bundled and shown by `LicensesView` in the account screen. Nothing in the repo generates it: update it by hand when a dependency changes. `Resources/PrivacyInfo.xcprivacy` declares no tracking and no collected data; `ITSAppUsesNonExemptEncryption` is `true` in `Info.plist` because of OpenPGP.

## Architecture

`XMPPClient` (`Sources/XMPP/`) is the single source of app state: an `ObservableObject` created in `PsiMobileApp` and passed to all views through `environmentObject`. Views read its `@Published` state and call its methods; they do not touch XMPPFramework.

- **Threading:** `XMPPClient` is `@MainActor`, but its XMPPFramework delegate methods are `nonisolated` and use `MainActor.assumeIsolated`. This is only safe because the delegates are registered with `delegateQueue: .main`; keep that for any new delegate or module.
- **Keys:** `contacts` and `messages` are keyed by bare JID.
- **Persistence:** contacts are in memory only. Messages go to `HistoryStore` (one JSON Lines file per contact, plaintext, excluded from backups) and are loaded per chat on first use. History files and Keychain items are closed while the phone is locked; messages arriving then wait in `HistoryStore.pending`. Chats where encryption was turned off by hand are in `UserDefaults` (`pgp.disabledChats`). The JID, host and port are in `@AppStorage`.
- **Presence:** the user's own status is always online, with no way to pick another; `state` holds the real connection state. The app reconnects when it returns to the foreground, but iOS still drops the connection in the background. The account password is in the Keychain through `Credentials` (`Sources/UI/AccountView.swift`). PGP keys are in the Keychain through `KeyStore`.
- **TLS:** normal chain and hostname validation runs first. If it fails, the only accepted certificate is the one whose SHA-256 matches `KeyStore.certPin` (the equivalent of Psi+'s `override-certificate`, kept in the Keychain so a tampered backup cannot plant it). The pin is set only by the import, is bound to one domain, has no UI, and is deleted as soon as normal validation passes; `tlsPinned` shows a warning in the account screen meanwhile. `KeyStore.migratePin()` moves pins that older versions kept in `UserDefaults`.
- **Timestamps:** `<delay>` (XEP-0203) is trusted in rooms, but in 1:1 chats only when its `from` is the user's own server, so a contact cannot backdate a message into old history.
- **Blocking and reports:** `XMPPClient.block(_:report:)` sends XEP-0191 blocking with an optional XEP-0377 report (`ReportReason`); the UI is the lock icon in a chat and the occupant menu in a room. App Review expects this to stay reachable.
- **Psi+ import:** `scripts/import-psi.py` also copies chat history (re-running it adds no duplicates; chats from the servers listed in the script's `OLD_DOMAINS` merge into the same login on the current server). It drops a one-shot JSON file into the app's Documents; `PsiImport` (`#if DEBUG`) moves it into the Keychain at launch, deletes it, and writes a secret-free `psi-import-status.json` that the script prints. Psi+ keys live in MacGPG (`/usr/local/bin/gpg`), not in the Homebrew `gpg` store.

### PGP (`Sources/PGP/`)

`PGPService` and `KeyStore` are singletons. `PGPService` caches the unlocked own keyring, so call `resetCache()` whenever the own key changes.

XEP-0027 wire format, which must stay compatible with Psi+/Gajim:

- Payloads are ASCII armor without the BEGIN/END lines or headers; `Armor.strip` and `Armor.wrap` convert to and from this form.
- Messages go in `<x xmlns='jabber:x:encrypted'>`, encrypted to the contact's key and to the user's own key. `<body>` carries only a placeholder.
- Presence carries a detached signature of the status text in `<x xmlns='jabber:x:signed'>`.
- Encryption is on for every contact with a known public key (`XMPPClient.isEncrypted`) unless turned off by hand with the lock icon; an incoming encrypted message turns it back on.
- Outgoing messages are not signed, to stay safe with Psi+/gpg. Incoming ones are checked against the contact's key when signed (lock and checkmark); a lock alone does not prove the sender. The marks are images, not text, so a message body cannot imitate them.

Untrusted input: roster IQs are accepted only from the user's own account or without `from` (`isForgedRosterIQ`). Presence and messages from JIDs outside the roster are held in bounded memory queues only until the roster loads, and are never shown or written to disk unless that contact appears. Login is SCRAM-SHA-1 only (`CheckedSCRAM`), with TLS 1.2 or newer. `send` refuses rather than falls back to plaintext when encryption is expected and the key is missing or unreadable (`isEncrypted`, `pgpExpected`). Keep these checks when adding stanza handlers.

### UI (`Sources/UI/`)

Colors and fonts are in `PsiTheme`, taken from the Psi+ defaults. The app forces the light color scheme. Follow Psi+ behavior when adding features, such as roster ordering and group sorting (`XMPPClient.groupedContacts`).

## App Store

`AppStore/` holds the listing text, the privacy policy (Russian and English) and export-compliance notes; placeholders in square brackets (`[EMAIL]`, `[ДАТА]`, test accounts) are still unfilled, and `AppInfo.supportURL` in `AccountView.swift` is `nil`. Screenshots in `AppStore/screenshots/` are taken from the `-psiDemo` simulator build. Version is `CFBundleShortVersionString` in `project.yml`; `release-build.sh archive` sets the build number from the current time.

## Not implemented yet

Working push: the client half exists (`account.pushService`) but needs the `aps-environment` entitlement and a push service, so no messages arrive in the background. Also XEP-0198, Carbons, MAM, contact management (add, rename, remove), password-protected rooms and bookmarks.

## Removing data

`XMPPClient.wipeAccount()` erases the password, keys, history and account settings; it runs from the account screen and when the JID is changed to another account. iOS can keep Keychain items after the app is deleted, so `KeyStore.clearAfterReinstall()` erases them on the first launch of a new install. While the app is inactive, `PrivacyCover` hides the screen from the app switcher snapshot.

## Conferences

Rooms (XEP-0045) live in `XMPPClient.conferences`; only the address and nick persist. Own messages are not appended on send: the server reflects them and `handleRoomMessage` marks them by nick. Rooms are unencrypted. To exercise stanza handling without a server, use the `-psiDemoRoom` flags described under Commands.
